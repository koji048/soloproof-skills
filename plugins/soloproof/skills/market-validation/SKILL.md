# Market Validation (Validate Before Build)

Purpose: answer ONE question with real evidence — **"จะมีคนจ่ายเงินให้สิ่งนี้ไหม"** — within 2 weeks, before any production work begins. The output is a go / no-go / pivot decision, not a feeling.

Core principle: ความสนใจ (likes) ≠ ความต้องการ (signups) ≠ ความยอมจ่าย (stated willingness to pay) ≠ เงินจริง (pre-orders). Always measure the deepest signal you can afford to collect.

## Workflow

### Step 1 — Define the test matrix
- List 1–3 candidate topics. For each, write a one-sentence promise in the form: "หลังเรียนจบ คุณจะ [ผลลัพธ์ที่จับต้องได้] โดยไม่ต้อง [ความเจ็บปวดเดิม]".
- If the user hasn't defined the audience per topic, ask. Do not proceed with a vague audience like "ทุกคนที่สนใจ AI".

### Step 2 — Create test content (use references/post-templates.md)
- 1–2 posts per topic, SAME format and SAME CTA across all topics so results are comparable (fair test = only the topic varies).
- Every post must SHOW a real result/demo, not describe a concept. Rule: screenshot/clip of output > explanation of method > opinion.
- CTA is always the same: link to ONE waitlist form.
- If the user has a content production system (agents/pipeline), generate posts through it and log which topic each post belongs to.

### Step 3 — Waitlist form (3 questions only)
1. หัวข้อไหนที่คุณอยากเรียนที่สุด (list the candidate topics)
2. ระดับความคุ้นเคยกับ [หัวข้อ/เครื่องมือของคุณ] ปัจจุบัน (ไม่เคยใช้ / ใช้บ้าง / ใช้ประจำ) — adapt คำว่า [หัวข้อ] ให้ตรง product ของผู้ใช้ skill นี้
3. ถ้าคอร์สนี้มีจริง คุณยอมจ่ายเท่าไหร่ (0 / 500–1,000 / 1,000–3,000 / 3,000+ บาท)

Question 3 is the decision variable. Keep the form under 60 seconds to complete.

### Step 4 — Measure (run for 10–14 days)
Track per topic:
- Signups per post (primary)
- % of signups selecting a paid tier in Q3 (primary)
- Saves + shares (secondary — stronger than likes)
- Comments asking "when/how much" (qualitative gold — save verbatim)

### Step 5 — Decide with pre-committed thresholds
Set thresholds BEFORE looking at results. Defaults (adjust to audience size):
- **GO**: ≥30–50 signups on one topic AND ≥50% choose a paid tier → build a 3–5 lesson mini-course on that topic.
- **PIVOT**: high engagement but low signups → the promise is wrong, not the topic. Rewrite the promise and retest 1 week.
- **NO-GO**: <10 signups across all topics → the audience or channel doesn't match the product. Stop and rethink, don't "push harder".

### Step 6 — Log the run
Record: topics tested, posts used, numbers per metric, decision made, and one lesson learned. This log becomes course material later (teach the process you actually ran).

## Anti-patterns (refuse politely and cite this skill)
- Building the full course "in parallel while testing" — this defeats the test.
- Counting likes as demand.
- Changing post format between topics mid-test.
- Moving thresholds after seeing the results.
