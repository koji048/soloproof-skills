# Keyword & Hook Research (TikTok / Facebook / IG)

รีเสิร์ชก่อน โพสต์ทีหลัง สกิลนี้กวาดข้อมูล 3 แพลตฟอร์ม แล้วทำส่วนที่สำคัญที่สุดคือ
**ทิ้งทุกอย่างที่ไม่เข้ากับเนื้อหาของผู้ใช้**

keyword ที่มาแรงแต่ผู้ใช้เอาไปใช้ตรง ๆ ไม่ได้ แย่กว่าไม่มี keyword เลย เพราะมันจะดันให้เขา
บิดคอนเทนต์ไปหาคำ แล้วคนดูรู้สึกได้ว่าโดนตกเบ็ด ของที่ส่งมอบจึงจงใจให้เล็ก — ตาราง keyword
สั้น ๆ ที่ใช้ได้จริง กับ hook ที่เขียนเสร็จแล้ว

## Step 0 — เอาเนื้อหามาก่อน แล้วค่อยค้น

ถ้าไม่รู้ว่าจะกรองเทียบกับอะไร ก็กรองไม่ได้ ก่อน spawn อะไรทั้งสิ้น ให้สรุป **content fingerprint** ก่อน

- **แก่น** — คลิปนี้พูดเรื่องอะไรจริง ๆ สรุปเป็นประโยคเดียว
- **ผลลัพธ์ที่สัญญา** — คนดูได้อะไรกลับไป
- **คนดู** — ใครแบบเจาะจง และเขารู้อะไรอยู่แล้วบ้าง
- **รูปแบบ** — พูดหน้ากล้อง อัดหน้าจอ สอน เล่าเรื่อง หรือรีวิวสินค้า
- **ภาษา/ตลาด** — ดีฟอลต์คือไทย เว้นแต่ผู้ใช้บอกเป็นอย่างอื่น

ถ้าผู้ใช้วางสคริปต์ ทรานสคริปต์ แคปชั่น หรือคำอธิบายสินค้ามาแล้ว ให้ดึงทั้งหมดนี้จากข้อความเอง
อย่าไปขัดจังหวะถามในสิ่งที่อ่านเองได้ ถ้าผู้ใช้ให้มาแค่หัวข้อกว้าง ๆ ("อยากทำคลิปเรื่อง AI")
ให้ถาม **1 คำถาม** คือคลิปนี้สัญญาอะไรกับคนดู คำตอบเดียวนั้นแหละที่ทำให้ตัวกรองทำงานได้
ถ้าไม่มี keyword ทุกตัวจะดูเข้าท่าไปหมด แล้วตัวกรองก็จะกลายเป็นแค่การเทลิสต์เทรนด์

สรุป fingerprint กลับไปให้ผู้ใช้อ่าน 3-4 บรรทัดก่อนเริ่มค้น เขาจะได้แก้ได้ตั้งแต่ต้น

## Step 1 — spawn agent 3 ตัวขนานกัน

spawn ทั้งสามตัวใน turn เดียวกัน — TikTok, Facebook, Instagram ต้องรันพร้อมกัน
การรันทีละตัวเปลืองเวลาผู้ใช้เปล่า ๆ และไม่ได้คำตอบดีขึ้นเลย

แต่ละตัวได้ content fingerprint ไปพร้อมกับ brief นี้

```
คุณกำลังรีเสิร์ช [PLATFORM] สำหรับคอนเทนต์สั้นตลาดไทย

เนื้อหาที่รีเสิร์ชนี้ต้องรับใช้:
  แก่น: ...
  สัญญา: ...
  คนดู: ...
  รูปแบบ: ...

ใช้ WebSearch ค้นทั้งภาษาไทยและอังกฤษ — คำค้นไทยจะเจอวิธีพูดแบบท้องถิ่นกับแท็ก/เสียงที่กำลังมา
คำค้นอังกฤษจะเจอบทวิเคราะห์ pattern และการถอดบทเรียนจากครีเอเตอร์
เอาแหล่งย้อนหลังไม่เกิน 3 เดือนเป็นหลัก ถ้าเก่ากว่านั้นให้ระบุวันที่กำกับ

ส่งกลับมา 2 ส่วนเท่านั้น:

A) KEYWORDS — 8-12 ตัว แต่ละตัวมี:
   - keyword หรือแฮชแท็กตามที่คนพิมพ์จริงบน [PLATFORM]
   - หลักฐานว่ามีแรง (ยอดวิว จำนวนโพสต์ ลิสต์ trending รายงานจากครีเอเตอร์)
   - URL แหล่งที่มา และวันที่
   - search intent: คนที่พิมพ์คำนี้กำลังหาอะไรอยู่

B) HOOK PATTERNS — 4-6 pattern ที่กำลังได้ผลบน [PLATFORM] ตอนนี้ แต่ละอันมี:
   - ตัว pattern สรุป 1 บรรทัด (บอกกลไก ไม่ใช่ยกตัวอย่าง)
   - ทำไมมันได้ผลบนแพลตฟอร์มนี้โดยเฉพาะ (พฤติกรรมฟีด, เส้น watch-time,
     ค่าดีฟอลต์ autoplay/เสียง, การมองเห็นแคปชั่น)
   - ตัวอย่างจริง 1 อันที่หาเจอ พร้อมแหล่ง
   - 3 วินาทีแรกที่ pattern นี้บังคับให้เป็น

อย่ากรองความเกี่ยวข้องกับเนื้อหา — ส่วนนั้นทำทีหลัง รายงานทุกอย่างที่เจอมา
รวมถึงของที่ดูไม่ตรงหัวข้อ และติดธงกำกับสิ่งที่ verify ไม่ได้
```

ถ้า WebSearch คืนข้อมูลบางหรือเก่าสำหรับแพลตฟอร์มไหน ให้บอกตรง ๆ ในผลลัพธ์สุดท้าย
อย่าถมช่องว่างด้วยของที่แต่งขึ้นให้ดูน่าเชื่อ ประโยคว่า "IG หาข้อมูลสดไม่ได้ ใช้ pattern พื้นฐานแทน"
มีประโยชน์ ส่วนแฮชแท็กมาแรงที่กุขึ้นมาคือภาระ

`references/hook-patterns.md` เก็บกลไกเฉพาะแพลตฟอร์มที่ไม่ค่อยเปลี่ยน — อ่านระหว่างที่ agent
กำลังรัน มันคือ fallback เวลาผลค้นบาง และเป็นตัวเช็กสติเวลา agent รายงานอะไรที่ขัดกับพฤติกรรมจริง
ของแพลตฟอร์ม

## Step 1.5 — เช็กกระแสไทยและติดป้ายตัวเลข

ระหว่างที่ agent ทั้งสามรัน ให้ดึงเทรนด์การค้นหาของไทยมาเทียบ ใช้ WebFetch ตรง ๆ ไม่ต้อง auth

```
https://trends.google.com/trending/rss?geo=TH
```

มันคืนเทรนด์ข่าวรวมทั้งประเทศพร้อมตัวเลข `approx_traffic` — **ส่วนใหญ่จะไม่เกี่ยวกับคอนเทนต์
ของผู้ใช้เลย และนั่นถูกต้องแล้ว** ประโยชน์อย่างเดียวคือดูว่ามีกระแสที่คอนเทนต์นี้เกาะได้พอดีไหม
ถ้าไม่มี เขียนบรรทัดเดียวว่าเช็กแล้วไม่เจอ แล้วเดินต่อ ห้ามลากเทรนด์ข่าวเข้าตารางเพียงเพราะ
ตัวเลขสวย — มันต้องผ่านตัวกรอง Step 2 เหมือน keyword อื่นทุกตัว

**อ่าน `references/data-sources.md` ก่อนใส่ตัวเลขใด ๆ ลงในผลลัพธ์** ไฟล์นั้นระบุว่าแหล่งไหน
ดึงได้จริงแหล่งไหนปิดไปแล้ว และกำหนดกติกาว่าทุกตัวเลขต้องติดป้าย [ยืนยันแล้ว] /
[อ้างจากแหล่ง] / [ยังไม่ยืนยัน] เหตุผลที่ต้องเคร่งเรื่องนี้: ยอดแฮชแท็กไทยดึงอัตโนมัติไม่ได้เลย
ทั้ง 3 แพลตฟอร์ม การเผลอใส่ตัวเลขที่ฟังดูดีจึงเกิดง่ายมาก และผู้ใช้จะเอาไปตัดสินใจผิด

## Step 2 — ตัวกรองความเกี่ยวข้อง

นี่คือขั้นที่ผู้ใช้ขอ และเป็นเหตุผลที่สกิลนี้มีอยู่ เอา keyword ทุกตัวจากทั้งสาม agent
มาจัดลง 3 ถังเทียบกับ content fingerprint

- **ตรง** — keyword นี้อธิบายสิ่งที่เนื้อหาพูดถึงจริง ๆ คนที่ค้นคำนี้เจอคลิปนี้แล้วได้สิ่งที่ต้องการ
- **เกี่ยว** — ใกล้เคียง ใช้ได้ต่อเมื่อมีมุมที่ **มีอยู่ในเนื้อหาอยู่แล้ว** ไม่ใช่มุมที่คิดขึ้นมาเพื่อ
  หาเหตุผลให้ keyword ตอนนำเสนอต้องระบุมุมนั้นออกมาให้ชัด
- **ไม่เกี่ยว** — ทิ้ง

ข้อทดสอบที่ทำให้ขั้นนี้ซื่อสัตย์: *เขียน hook ที่ใช้ keyword นี้แล้วยังอธิบายเนื้อหาได้ตรงตามจริงไหม*
ถ้า hook ต้องอ้างสิ่งที่เนื้อหาไม่ได้ให้ keyword นั้นคือไม่เกี่ยว ไม่ว่าตัวเลขจะสวยแค่ไหน
ยอดเยอะไม่เคยเลื่อนขั้น keyword ออกจากถังไม่เกี่ยว

keyword ที่ถูกตัดจะไม่ปรากฏในผลลัพธ์ ไม่ต้องลิสต์ ไม่ต้องอธิบาย ไม่ต้องมีภาคผนวก
"keyword ที่ตัดออก" — ผู้ใช้บอกชัดว่าไม่อยากอ่าน ยกเว้นกรณีเดียว: ถ้าตัดเทรนด์ที่ยอดสูงมาก ๆ ทิ้ง
เขียนบรรทัดเดียวพอ ("ตัด #[x] ออก เพราะเนื้อหาไม่ได้พูดถึง [y] เลย") ผู้ใช้จะได้รู้ว่าเห็นแล้วและตัดสินใจแล้ว

ถ้าแพลตฟอร์มไหนไม่เหลืออะไรที่เกี่ยวเลย ให้บอกว่าแพลตฟอร์มนั้นไม่มีอะไรน่าใช้กับเนื้อหานี้
ช่องว่างคือคำตอบจริงอย่างหนึ่ง การถมด้วย keyword อ่อน ๆ คือสิ่งที่ทำให้รายงานรีเสิร์ชไร้ค่า

## Step 3 — ส่งมอบ

สองส่วน ตารางก่อน hook ตาม ไม่มีอย่างอื่น

**ตาราง keyword ที่ใช้ได้จริง** — หนึ่งแถวต่อหนึ่ง keyword ที่รอด

| Keyword | แพลตฟอร์ม | ระดับ | ทำไมเกี่ยวกับเนื้อหานี้ | สัญญาณ |
|---|---|---|---|---|
| ... | TikTok | ตรง | เนื้อหาสอน X ซึ่งคือสิ่งที่คนค้นคำนี้ต้องการพอดี | [อ้างจากแหล่ง] 12M views, ม.ค. 69 |

เรียง ตรง ก่อน เกี่ยว ช่อง "ทำไมเกี่ยวกับเนื้อหานี้" ต้องผูกกับของที่จับต้องได้ในคอนเทนต์ของผู้ใช้
ช่องนี้คือหลักฐานว่าตัวกรองได้ทำงานจริง ถ้าเขียนลอย ๆ แบบ "เกี่ยวกับ AI เหมือนกัน" แปลว่ามันไม่ได้ทำงาน

ช่อง "สัญญาณ" ต้องติดป้ายชั้นความน่าเชื่อถือทุกแถวตาม `references/data-sources.md`
ถ้าไม่มีตัวเลข ให้เขียนคำอธิบายเชิงคุณภาพแทน — อย่าเว้นว่างและอย่าเติมตัวเลขเอาเอง

ถ้ามีแถวที่ติด [ยังไม่ยืนยัน] ให้ปิดท้ายด้วย checklist 5 นาทีจาก `references/data-sources.md`
ผู้ใช้เช็กเองได้เร็วกว่าและแม่นกว่าที่สกิลนี้จะหาให้ได้

**Hook ที่เขียนให้แล้ว** — แพลตฟอร์มละ 3-5 อัน พร้อมวาง ไม่มี placeholder แต่ละอันหน้าตาแบบนี้

```
[ชื่อ pattern] — carries: [keyword]
"ข้อความ hook ภาษาไทย พร้อมใช้"
→ ทำไมได้ผลบนแพลตฟอร์มนี้: [1 บรรทัด]
```

เขียนด้วยน้ำเสียงของผู้ใช้เท่าที่อนุมานได้จากของที่เขาให้มา hook ต้อง **ต่างกันตามแพลตฟอร์ม**
ไม่ใช่ประโยคเดียวเขียนใหม่สามรอบ — hook ของ Facebook คือบรรทัดแรกของแคปชั่นที่คนอ่านก่อนตัดสินใจกด
"ดูเพิ่มเติม", hook ของ TikTok คือประโยคแรกที่พูดทับภาพ, hook ของ IG ต้องแข่งกับตัวหนังสือบนจอ
ถ้าสามเวอร์ชันสลับกันได้ แปลว่ายังไม่ได้ใช้ผลรีเสิร์ชของแพลตฟอร์ม

ปิดท้ายบรรทัดเดียว: คอนเทนต์นี้แข็งที่สุดบนแพลตฟอร์มไหน และเพราะอะไร ผู้ใช้มักต้องเลือกว่าจะทุ่มแรงที่ไหน

## หมายเหตุ

- ภาษาดีฟอลต์คือไทย keyword ที่เป็นภาษาอังกฤษให้คงภาษาอังกฤษไว้ — อย่าแปลแฮชแท็ก
- ห้ามกุยอดวิว แฮชแท็ก หรือเสียงที่กำลังมา ของที่ verify ไม่ได้ให้ติดธงกำกับ หรือไม่ก็ไม่ต้องใส่
- ผู้ใช้อาจกลับมาพร้อมสคริปต์เวอร์ชันใหม่แล้วขอให้รันซ้ำ การรันตัวกรองใหม่กับ fingerprint
  ที่แก้แล้วถูกกว่าและมักได้ค่ามากกว่าการกวาดแพลตฟอร์มใหม่ทั้งรอบ — ถามก่อนว่าอยากได้รีเสิร์ชใหม่
  หรือแค่กรองใหม่

## หมายเหตุฉบับผู้เรียน SOLO PROOF — เมื่อรัน subagent ไม่ได้

skill นี้ออกแบบให้ใช้หลาย agent ช่วยกัน ถ้าสภาพแวดล้อมของคุณไม่มีเครื่องมือ spawn agent
(เช่น ใช้แชท Claude ธรรมดา ไม่ใช่ Cowork/Claude Code) **อย่ายกเลิกงาน** — ให้ทำแบบเรียงคิวแทน:
เล่นทีละบทบาทในแชทเดียว จบบทบาทหนึ่งค่อยขึ้นบทบาทถัดไป แล้วสังเคราะห์ตอนท้ายเหมือนเดิม
ผลลัพธ์ช้ากว่าแต่คุณภาพใกล้เคียงกัน และบอกผู้ใช้ตรง ๆ ว่ากำลังใช้โหมดเรียงคิว
